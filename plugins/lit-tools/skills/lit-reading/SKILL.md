# 讀文獻：AI 工作指令

讀文獻的結果要**接回文獻庫**：每次讀完都留下 AI 筆記、灰色標註、AI 閱讀紀錄，文章頁才會顯示「AI 讀到哪裡」並連到筆記。
搜尋、加入文章、改狀態等管理工作用 `lit-library` skill；規則的唯一來源是 `lit-library` skill 資料夾裡的 `規則.md`（§5 標註、§7 閱讀程度、§8 依據）。

工具（從 vault 根目錄執行；Python 指令 Windows 用 `python`，macOS／Linux 用 `python3`）：
- `L` = `python "${CLAUDE_PLUGIN_ROOT}/scripts/litlib.py"`（文獻庫）
- `Z` = `python "${CLAUDE_PLUGIN_ROOT}/scripts/zot.py"`（讀 Zotero PDF，唯讀）
- `A` = `python "${CLAUDE_PLUGIN_ROOT}/scripts/zotann.py"`（寫灰色標註）

`${CLAUDE_PLUGIN_ROOT}` 沒有被換成實際路徑時，用載入本 skill 時顯示的 base directory 往上兩層（`<base>/../../scripts/`）。

## 1. 找到文章

1. `L rebuild`，再 `L find "作者 關鍵字"` → citekey 與狀態。
2. `Z find "作者 關鍵字"` → **附件代號**（PDF 附件的 key，不是條目 key）。
3. 不在 Zotero：`L fetch <DOI>` 看有沒有免費全文連結，有就讀那個版本（記下是預印本還是期刊版）。沒有就告訴使用者需要下載，**只根據摘要回答時要明說**。
4. 找既有的 AI 筆記：`2_paper/AI筆記/{citekey} AI筆記.md`。有就先讀，避免重讀已經整理過的內容。

## 2. 讀

- 先定位再讀：`Z grep <附件代號> "正規式"` 找出相關頁，`Z page <附件代號> <頁>` 讀那幾頁。使用者要求精讀或整理全篇時才逐頁讀完。
- 補充資料（Supplementary）通常是另一個附件，`Z find` 會列出。
- 要讓使用者看原文時：`Z open <附件代號> <頁>` 在 Zotero 閱讀器打開到該頁。

## 3. 回答

- 重點句附**頁碼與原文**：`p.5「…原句…」`。
- 分清楚三種內容：**論文寫的**、**我的推論**（標「推論」）、**論文沒寫的**（直接說沒寫，不要補）。
- 和使用者研究主題（`2_paper/文獻庫資料/設定.json` 的「研究主題」）有關的地方，另外點出來。

## 4. 留下紀錄（每次回答後都做，不用問）

### 4.1 灰色標註

把回答中引用的原句標在 PDF 上（規範：規則 §5.2）。
- **回答問題時自動標**，不用先問。使用者不同意可以直接刪。
- **整段標**：`text` 放評論所依據的完整論述（前因＋主張＋作者的理由或限定，通常 2～5 句），不要只放一句；不跨頁，相鄰標註不重疊。
- 一律灰色 `#aaaaaa`；分類 tag 只能是 `論點`、`質疑`、`方法`、`數據`、`待查`、`本研究`（腳本會加 `AI/` 前綴）。
- 評論寫一到兩句說為什麼標，開頭加 `〔問：問題的簡短版〕`；和任務有關時填 `task`。評論**專有名詞用英文**，例：`〔問：nonlinearity 怎麼定義〕作者用 log–log slope 量 nonlinearity，linear = 1`。
- 只標真正有用的地方。先 `A list <附件代號>` 看已有哪些、避免重複。
- 只動自己的灰色標註，不碰使用者的彩色標註。

步驟：
1. 寫 JSON 到暫存檔：
   ```json
   [{"page": 5, "text": "PDF 原句", "tag": "數據", "comment": "〔問：吸收率多少〕吸收率 0.95 的出處", "task": "intro"}]
   ```
   句子照 PDF 原文抄；行尾斷字寫成完整單字即可，腳本會處理。`page` 是 PDF 第幾頁（從 1 起算），不是印刷頁碼。
2. 預覽：`A add <附件代號> <json>`，修到沒有「找不到」。
3. 寫入：同一行加 `--send`。記下回傳的標註代號，寫進 AI 筆記。
4. 刪除自己的標註：`A delete <標註代號>... --send`（腳本只刪得掉灰色）。

需要 Zotero API 金鑰（`~/.config/zotero/api_key`）；沒有就請使用者用 `lit-setup` skill 設定（或跟 Claude 說「設定 lit-tools」）。附件要已同步到 zotero.org，網路 API 才找得到。

### 4.2 AI 筆記

位置：`2_paper/AI筆記/{citekey} AI筆記.md`，**每篇一份**，同一篇的問答都追加在同一份。第一次建立時用這個格式：

```markdown
---
citekey: {citekey}
type: ai-note
---

# {citekey} AI 筆記

> Claude 讀這篇時的筆記。文章頁：[[{citekey}]]｜閱讀卡：[[{citekey} 閱讀卡]]（沒有閱讀卡就省略）
> 讀的版本：期刊版／預印本（PDF 附件代號 XXXXXXXX）

## 整體摘要

（精讀全文後才寫；只讀部分時寫「尚未精讀全文」）

## 問答紀錄

### YYYY-MM-DD 問：使用者的問題
- **答**：精簡的結論（幾句話）。
- **依據**：p.5「原句」；p.7 Fig. 3。
- **推論**：（有的話）
- **讀了**：p.1–2、5–7
- **標註**：TMMF4ZKK、UB3PAREQ

## 相關筆記

- [[{citekey}]]
```

- **專有名詞用英文**：句子結構用中文，物理量、現象、方法、元件、論文用語直接寫英文。欄位標題和一般動詞、連接詞維持中文；原文引述照抄不動。縮寫第一次出現寫全稱，例：signal-to-noise ratio（SNR）。
- 新問答追加在「問答紀錄」最後，不改寫舊的；舊的錯了就在新的一則說明更正。
- 精讀全文後補「整體摘要」（核心論點、方法、關鍵數據、和使用者研究的關係、侷限）。
- 篇幅大的分析可以另開筆記（放使用者慣用的筆記資料夾），再從 AI 筆記的「相關筆記」連過去。
- 建立 AI 筆記時，用 Grep 找 vault 裡有沒有這篇的舊筆記（搜作者名、標題關鍵字、citekey），有就列進「相關筆記」。

### 4.3 AI 閱讀紀錄

讀的範圍變深時才寫（同樣深度的再次提問不用重寫）。把 JSON 寫進暫存檔再 `L log AI閱讀 <檔案>`：

```json
{"文章": "<DOI>", "程度": 2, "依據": "全文", "版本": "期刊版", "主要貢獻": "一句話", "筆記": "[[citekey AI筆記]]"}
```

- 程度：2 = 讀了部分內文（引言、相關段落、圖、結論）；3 = 讀完全文。
- 依據：讀了內文就填「全文」。
- 主要貢獻：讀了內文後若比原本只根據摘要寫的更準確，就改寫；否則沿用原句。
- 寫完 `L rebuild`。

## 5. 回報

回答的最後一行簡短交代留下了什麼，例如：
`已記錄：AI 筆記 [[citekey AI筆記]]、灰色標註 3 則（p.5、p.7）、AI 閱讀程度 1 → 2`

## 多篇比較

使用者問「A 和 B 的做法差在哪」：每篇各自走 1–4（各自的 AI 筆記與標註）；比較結果本身寫在回答裡，值得保存時另開筆記，並從各篇 AI 筆記的「相關筆記」連過去。
