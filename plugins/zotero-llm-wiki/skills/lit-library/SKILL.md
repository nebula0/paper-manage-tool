# 文獻管理系統：AI 工作指令

**規則的唯一來源**是本 skill 資料夾裡的 `規則.md`。開始前先讀它；本檔只寫「怎麼做」，不重複規則。

## 工具與路徑

- 腳本在外掛的 `scripts/` 資料夾：`${CLAUDE_PLUGIN_ROOT}/scripts/`。如果這段文字沒有被換成實際路徑，就用載入本 skill 時顯示的 base directory 往上兩層（`<base>/../../scripts/`）。
- Python 指令：Windows 用 `python`，macOS／Linux 用 `python3`。
- 以下 `L` 代表 `python "${CLAUDE_PLUGIN_ROOT}/scripts/litlib.py"`。**從使用者的 vault 根目錄執行**（腳本會往上找 `2_paper/文獻庫資料` 或 `.obsidian` 來定位 vault）。
- 研究主題、本團隊名單、標籤詞表在 `2_paper/文獻庫資料/設定.json`。判斷相關性前先讀「研究主題」。
- 找不到 `2_paper/文獻庫資料/設定.json`：使用者還沒設定，請他先用 `lit-setup` skill 設定（或跟 Claude 說「設定 zotero-llm-wiki」）。

## 通用規則

1. **書目資料從資料庫抓**（OpenAlex、Crossref、Better BibTeX），不憑記憶填 DOI、年份、期刊、摘要。
2. **每篇新抓的文章寫兩句**：
   - 主要貢獻：一句，後面標依據等級（全文／摘要／他人描述／僅書目／AI 記憶）。
   - 為何抓：一句，附日期與任務。
3. **依據只有「僅書目」或「AI 記憶」的，只能列為候選**，不給必引度。
4. **排除的文章也列出來**，附一句理由。
5. **不用程式大量下載期刊 PDF。** 全文先找合法免費版本，沒有就列入使用者的下載待辦。
6. **不直接寫 `zotero.sqlite`。** 讀取用唯讀模式；寫入只走 Zotero 網路 API。
7. **不直接編輯文章頁（`2_paper/文獻庫/*.md`）或它的檔頭。** 文章頁由重建腳本產生；要改狀態、主要貢獻、為何抓，就追加紀錄再重建（規則 §0）。

## 文獻庫

- **做任何文獻工作前**：`L rebuild`，讓文章頁反映 Zotero 最新狀態。
- **搜尋前**：`L find "關鍵字"` 或 `L find <DOI>`，查文獻庫與過去的搜尋紀錄，避免重搜。
- **查一篇文章**：`L fetch <DOI>`，看書目、摘要、免費全文（結果自動進快取）。

### 搜尋文獻（主要流程）

**原則：Claude 自己在主對話裡逐步搜尋、判斷相關性；文獻庫負責記錄與去重。** 不把「發現」交給代理（代理不知道研究脈絡，照字面執行容易偏題）。

1. **查庫**：`L rebuild`，再 `L find "關鍵字"` 看庫內已有什麼、以前怎麼搜過。
2. **綜述先行**（新主題的第一輪才做）：
   - 找 2–4 篇高被引綜述（庫內已有的優先；不夠再用網路搜尋與 `L fetch` 看被引次數）。
   - 用 `lit-reading` skill 讀全文（需要 PDF 在 Zotero 或有免費全文；沒有就列入使用者的下載待辦）。
   - 歸納成一份「機制地圖」筆記（放使用者慣用的筆記資料夾，沒有就放 `筆記/`）：有哪些機制或做法、各自的特點、代表文章。地圖的每一格就是之後要填的搜尋目標，綜述引用的代表文章就是種子。
3. **逐步搜尋**：一個機制（地圖的一格）一個查詢，看完結果再決定下一個查詢，不要一次塞多個機制。
   - 發現用網路搜尋（WebSearch），查詢字串用該機制的專有名詞。
   - 每格找到 1–2 篇核心文章後做引用追蹤：`L track <DOI> 往前|往後 --abs`，補想不到的方向。
   - `L search`（OpenAlex 關鍵字）只在需要結果數或要限定年份時用；泛的查詢會被高被引的一般綜述淹沒。
   - 量大的機械工作（例如對十幾篇種子做引用追蹤）才交給 `lit-search` 代理，prompt 要給任務代號、起點 DOI 清單、收錄標準、批次檔路徑。
4. **核對書目**：每篇候選都用 `L fetch <DOI>` 確認 DOI、年份、期刊、被引次數，不用搜尋引擎片段或 AI 記憶填書目。
5. **讀摘要再判斷**。摘要來源依序：OpenAlex（`L fetch`）→ arXiv 摘要頁 → Semantic Scholar 公開介面 → Crossref。
   - 讀到摘要原文：依據填「摘要」；不是從 OpenAlex 讀到的，批次檔要加「摘要來源」。
   - 只看到搜尋引擎片段或工具轉述：依據填「他人描述」。
   - 都沒有：依據填「僅書目」，仍可列候選，**不因為沒摘要就擠掉**。
6. **寫批次檔**（放暫存資料夾，如 scratchpad 的 `batch-日期-主題.json`；格式見 `litlib.py` 的 `import_batch` 說明或 `lit-search` 代理的範例）：
   - 每次查詢一筆「搜尋」。網路搜尋的資料庫填「WebSearch」，沒有結果數就不填。
   - 排除的也列，附理由。「已排除」之後搜尋會被標 ✗ 跳過，所以只排除確定不要的；拿不定的列候選。
   - `L import-batch <批次檔> --check` 修到通過。
7. **給使用者看過再匯入**：先跑 `L import-batch <批次檔> --preview`，產生 `2_paper/待匯入/{任務代號}.md`（同任務頁版型，新文章標 🆕），把連結給使用者，由使用者決定哪些要。對話中只簡短列出收錄（主要貢獻與依據）、排除與理由、建議先讀哪幾篇、需要的新 tag（要使用者同意才改詞表）。使用者同意後 `L import-batch <批次檔>`，再 `L rebuild`。
8. **任務頁**：重建會自動產生 `2_paper/任務/{任務代號}.md`。回報使用者時附上 `[[任務代號]]` 連結；不要手改。任務說明寫清楚「為了什麼找」，查詢的「說明」欄寫這一查想補哪一格。
9. 網路搜尋的排序不透明、不可重做，紀錄只代表「哪天查了什麼、收了哪幾篇」，不要當成系統性搜尋的證據。

### 個別紀錄

使用者說「這篇排除」「這篇要讀」「這篇引言要引用」、或 AI 讀得更深時，用 `L log`：
- **寫紀錄**：把 JSON 寫進暫存檔，`L log <類型> <檔案>`。類型依序：
  1. `任務`：新工作先登記（代號用短英文或中文，如 `intro-必引`）。
  2. `搜尋`：每次查詢一筆，回傳代號 `S日期-n`。
  3. `來源`：每篇找到的文章一筆，附搜尋代號與「為何抓」。
  4. `AI閱讀`：讀了摘要或內文就寫主要貢獻與依據；程度 2 以上要先存 AI 筆記再附連結。
  5. `標籤`：新文章依摘要給 1–2 個 `topic/…` 和 1 個 `type/…`，只能用 `設定.json` 的詞表；詞表不夠時先問使用者再改詞表。
  6. `決策`：候選／要讀／已排除（附理由）；引用時填角色與必引度。使用者說的話用 `"由": "使用者"`。
- 寫完紀錄再 `L rebuild`，把結果（新增幾篇、警告）告訴使用者。
- `rebuild` 列出 🗑 移除或 ⚠️ 警告時，要轉告使用者，不要略過。
- `rebuild` 列出 📝 的文章（多半是使用者剛存進 Zotero 的）：用 `L fetch <DOI>` 讀摘要，`L log AI閱讀` 寫主要貢獻、`L log 標籤` 給標籤，再重建。
- **暫定代碼轉正**：候選存進 Zotero 後，重建會用 BBT 的正式 citekey 建新頁、刪掉暫定代碼的舊頁（🗑）。兩者不同時，用 Grep 找 vault 內 `[[舊代碼` 的連結，改成新代碼，並告訴使用者改了哪些筆記。
- 不自行 git commit，除非使用者要求。
- 文章頁連結一律寫 `[[citekey]]`；要連閱讀卡寫 `[[citekey 閱讀卡]]`。

## 讀文獻與 AI 標註

讀文獻、回答論文內容的問題、在 PDF 上畫灰色標註，改用 **`lit-reading` skill**。它會留下 AI 筆記（`2_paper/AI筆記/{citekey} AI筆記.md`）、灰色標註與 AI 閱讀紀錄。
